## Retained component

The permitted whole sections are defaults directives, the 101-byte parent,
35-byte associated cleanup/handler, 44-byte associated FuncInfo/unwind metadata,
and a whole one-record SafeSEH table. Eleven DIR32/REL32 references are checked.
Both runtime children must physically associate with parent section 3. The
single state transitions from 0 to -1 through the owned cleanup. The handler,
cleanup, FuncInfo and unwind-map symbols stay local and role-owned; only the
parent is externally defined under its canonical unresolved-CODE pool identity.

The observer requires both v3 piece verdicts true, complete original field
inventory with no missing fields, exact parent proof, explicit own-source
external resolutions, matching original nonrelocation content, and every
original relocated destination/addend. It also replays the unchanged ordinary
and EH comparison core and requires exact compiled extent 101, both same EH
intervals true and no EH error. Additional fixed metadata checks are stricter
than that original core; they do not replace it. The parent/body match alone
cannot discharge a failed helper or an unknown metadata field.

The vtable record at index 16 may become undefined only with the explicit
original DATA boundary proof. This names an unresolved data obligation; no
vtable storage, RTTI, guessed type identity or provider is emitted. Other external
obligations use only the shared canonical roles `code`, `data`, `iat-cell`,
or `crt-contract`. The fixed vtable and cookie-data obligations hash as `data`; the two CRT
functions hash as `crt-contract`. Cookie data retains semantic subtype
`data/security-cookie` separately from its canonical role. Semantic domain (`data` or `code`)
and contract kind (vtable view, cookie, cookie check, or frame handler) remain
separate receipt fields; these do not enter the shared unresolved-symbol hash.
The shared name remains exactly the existing hash of original base and canonical
role. Equal proved base/role identities therefore produce the same shared name.

A required shared-base identity ledger must independently agree with every
external binding, including semantic domain and contract kind. Missing proof,
unknown canonical roles, incompatible role/domain pairs, and same-base canonical
role, semantic-domain or contract-kind conflicts fail closed. This also rejects cookie-data versus CRT-function conflation. The former
`crt-contract` cookie identity is preserved as a rejecting counterexample.
No compatible actual shared-base identity has been observed by this extension;
actual composition is still blocked. These synthetic guards are not evidence
that the real base identity has been proved. The ledger is included in the
hash-bound retention plan. Security-cookie data/check and normal CRT
frame handler remain unresolved obligations. Nothing disables SafeSEH, EH,
security instrumentation or library diagnostics.

## Synthetic serializer mechanics

The new adapter reuses the frozen namespace writer, selection serializer and
selection verifier. It retains primary/auxiliary bijections, section associations,
COMDAT policy, static offsets, string references, relocation records and addends.
After serialization it rebases the sole SafeSEH symbol-index record from old
physical index 19 to the mapped local handler index. Only that ordinal and the
rewritten registry section auxiliary checksum (set to zero) may differ from the
frozen writer output. The complete source CODE and state-table payloads are
preserved. A second parser independently checks section flags, payload hashes
and symbol/section counts. Only the canonical parent may be exported.

This API returns bytes in memory and a hash-bound report; it has no archive,
linker, compiler or execution operation. Unit tests write only authored synthetic
COFF to temporary files for parser/core verification. No game payload belongs
in tracked artifacts or summaries. A future real driver must stage and verify
before publication and bind the producer/consumer receipt versions and hashes;
this driver is intentionally unavailable now.
